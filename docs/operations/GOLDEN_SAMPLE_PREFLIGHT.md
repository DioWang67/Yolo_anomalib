# Golden sample 開線穩定性檢查

GUI 的「顏色開線檢查」現在使用獨立 golden sample 正常基準。原本的
`color_preflight` 分數餘裕設定與 CLI 保留作為舊版診斷，**不是這個開線判定**。

## 首次建立正常基準

「工程維護：基準與容許範圍」需要**工程 PIN**才會展開。每日開線不需要 PIN。
授權只針對這一次操作，不會開啟主畫面的工程頁 session，也不會啟用工程面板。

建立分成**兩步**：先量測，再依實測提議上限並由工程人員確認。
上限不需要事先憑感覺填入 —— 硬編碼的 3.00／1.00 會被誤讀為建議值，
而要求在還沒有任何量測前先填一個數字，得到的也只是另一種猜測。

1. 確認相機、曝光、白平衡、光源與治具處於已驗證的正常狀態，固定標準品。
2. 輸入可追溯的 golden sample 編號與建立人員，勾選環境已確認。
3. 按「① 收集 5 次並量測」。啟用相機輸入並完成系統初始化，系統自動依序執行 5 次檢測。
   每次檢測完成且影像證據收集成功後才啟動下一次；請保持樣品不動，不必切回主畫面。
   按「回主畫面（保留進度）」、右上角 X 或 Esc 只會隱藏視窗；背景繼續收集。
   再開啟同站點的「顏色開線檢查」會回到原本進度／結果，不需要再按建立基準。
   只有「取消本次收集」會中止；退出整個程式也會停止，未完成收集不跨重啟續接。
4. 量測完成後畫面顯示各位置實測波動，並填入**依實測提議的上限**與推導依據：
   - 連拍波動上限＝本次與過往取樣中最大的連拍波動 × 1.5
   - 最大區域色差上限＝過往取樣**以本次新基準重算**後的最大色差 × 1.5；
     沒有可重算的影像時暫以實測波動 × 3 推導，並提示累積數日後應重新檢討

   「過往取樣」是同一片 golden sample、同一組顏色設定下的每日檢查與封存基準，
   重新讀取當時的裁切圖、對位後與新基準比較（最多最近 60 次）。不再沿用檢查檔裡
   存的色差數字：那些是對著別的基準、而且在 v5 之前多半量到的是擺放位置。
   影像已被清除、樣品編號或設定不同、或影像無法對位的取樣會被略過；
   連拍波動超過絕對上限或色差距中位數超過 3 倍者視為異常，不用來放寬上限。
   不再要求曝光完全相同：照度迴路本來就會讓每天落在不同曝光，
   完全相同的條件只會讓歷史永遠是空的。依據會顯示在畫面上 ——
   沒有說明的數字只是另一個預填值。
5. 確認或自行調整上限後，按「② 接受上限並儲存正常基準」才寫入。
   全部生產顏色檢測合格、位置一致且波動在上限內才會通過。
   基準檔記錄 `limits_source` 為 `proposed`（接受提議）或 `adjusted`（自行調整），
   稽核時可區分「經過判斷」與「直接接受預設」。

無論如何，連拍波動都不得超過絕對上限 `MAX_ACCEPTABLE_JITTER`（6.0）——
提議上限是從被它評判的那次量測推導出來的，若無固定天花板，
站點就能通過自己剛剛替自己訂的標準，波動把關會失去意義。

更換基準是獨立工程操作，會封存舊基準。不要用重新建立基準消除當天偏移。
首次的 5 次取樣是重複性基準，不自動代表已涵蓋跨日環境變異。

## 每日開線

1. 視窗頂端顯示基準樣品編號與**本地時間**的建立時刻，以及站點就緒狀態。
   四項前置條件（站點一致、生產自動模式已停止、相機輸入、檢測系統已初始化）
   在按下開始**之前**就逐項顯示；任一項未就緒時「開始開線檢查」保持停用，
   並直接寫明卡在哪一項與排除方式。不會再發生按下去、等待、才被中止的情況。
2. 放入標準品，勾選確認後按「開始開線檢查」。系統自動執行 3 次檢測，
   收集時不更換樣品或相機設定。畫面只顯示一個進度來源：已收集張數。
3. 查看各位置最大色差、平均亮度差、連拍波動、辨識餘裕及原因。
4. 僅所有位置都通過時，顯示本次量測符合正常範圍。

判定為 NG 時，標題直接點名位置（例如「顏色偏移超限 — 位置 2 綠線」），
且異常位置的卡片會排在最前面，不會落在捲軸下方。

日常畫面預設為「影像對照」，每個位置並排顯示基準第 1 張實拍與本次色差最差的一張。
青框為取樣區域：基準圖上是建立時的位置，本次圖上是**自動對位後**實際量測的位置；
樣品放的位置與基準不同時，卡片會顯示「對位 +x, +y px」。
4×4 數值是各區域跨次最大色差，紅底表示超出保存的色差上限；
「—」是線緣、印字或端子等對擺放敏感、不列入判定的區域。
各格差異很小時（例如整體光源偏移）會收合為單一數值，避免十六個相同數字佔滿版面。
不同格的最大值可以來自不同張；基準圖片只是實拍範例，實際比較使用多張量測統計。
缺少圖片時顯示「尚無影像」，不以示意圖代替、不改變判定。

「數值明細」頁籤保留完整數字，顏色名稱與卡片一致。工程設定預設收起且需 PIN；
已有基準時欄位載入實際上限。外部更新基準後重新開啟隱藏視窗即可刷新。
判定區分檢查未完成、取樣位置／影像需確認、取樣不穩定、顏色偏移超限與辨識條件未通過。

程式同時檢查檔案修改時間與快照中的檢測時間，只納入開始之後的新結果。
需要啟用結果快照及每個顏色位置的裁切圖儲存。缺图、缺位置或無法判讀不會通過。
這是操作員開線依據，未新增 PLC 或生產啟動的硬體互鎖。

自動取樣期間不接受主畫面的手動檢測啟動；需先停止正在運作的生產自動模式。
使用真實相機取樣，不能用同一張靜態圖片重複檢測。相機錯誤會中止收集並顯示原因。

單次超過 120 秒未收到完整證據會中止。整場收集的時間預算隨張數縮放
（張數 × 120 秒再加 120 秒寬限），所以 5 張的基準建立不會因為單純的算術
而在中途逾時。

某一張的證據不完整時，會先重讀該檔 3 次（快照與裁切圖是分開寫入的，
通常只是還沒寫完）；仍不完整就**只丟棄那一張並重拍**，已收集合格的張數保留。
連續 3 張都不完整才停止整場收集。取消會停止後續取樣，已啟動的單次檢測可完成。

## 量測定義與限制

- 建基準時取各次裁切框的共同區域，再依位置容許偏移（框寬高的 15%）向內縮，
  保存影像座標，並把 5 張對位後的中位數影像存入基準檔（`template`，PNG）。
- **自動對位**：每次量測先在裁切圖中找出基準影像的位置（灰階正規化相關），
  再在那裡量測。操作員重放樣品時線材會移動 1–2 像素，而取樣區域只有約 20 像素寬，
  一個像素就足以讓線緣那一格從「線」變成「板子」。v4 用固定座標量測，
  Cable1/A 因此幾乎每次開線都判超限：2026-10-05 的 ΔE 35.6 對位後是 6.0，
  線身顏色其實沒變。正規化相關不受增益／偏移影響，所以對位本身不會吸收亮度漂移。
  對位分數低於 0.7 判「取樣對位失敗」—— 畫面已不是建立基準時的樣子
  （實測：重放樣品 0.89–1.00；2026-09-21 畫面整個改變的幾次 0.36–0.45）。
- **只量穩定像素**：基準影像中與任一相鄰像素差異超過 ΔE 6 的像素
  （線緣、印字、端子）不量測；這是依影像結構、不是依顏色決定，所以不會隱藏偏色。
  每格至少要有 8 個穩定像素才列入判定，每個位置至少要有 2 格，否則拒絕建立基準。
- **逐像素配對比較**：每個穩定像素與基準影像的同一像素相減（CIE Lab），
  各格取差值中位數。同一格同時含線與板子時也不會在兩者之間跳動。
  這是相機影像相對色差，不是校正色度計量測。
- ΔE76 是 Lab 歐氏距離，顯示所有判定格、所有張中的最大值。
  量測版本為 `golden-lab-registered-v5`，舊版基準需重新建立一次。
- 連拍波動是每格各次量測相對本次均值的最大 ΔE76；ΔL* 是判定格的平均亮度變化。
- 依原始 bounding box 與色別一對一匹配位置，不依 detector 回傳順序匹配。
  框的每個邊界最多偏移參考寬／高的 15%；無唯一對應即不通過。
- 任一張生產顏色檢測失敗，或最差餘裕低於基準的餘裕保留率，也不通過。
  保留率取自站點設定的 `color_preflight.minimum_margin_retention`（未設定時為
  0.6，與 CLI 版顏色開線檢查同一個值），建立基準時寫入基準檔，之後依該值判定。
- 取樣區域包含背景板；背景板與線身都受同一光源照射，兩者的偏移都代表環境變化。
  線緣、印字與端子不判定，因此**只出現在線緣的局部異常不會被看到**；
  小於一格半數穩定像素的局部異常也未必改變中位數。
  本功能用途是環境穩定性檢查，並非微小混色缺陷檢測。
- 基準綁定「會影響顏色量測的**工程設定**」與顏色模型**內容**的 SHA-256，
  不是整份設定檔的雜湊。納入的欄位是顏色檢查開關與類型、顏色模型路徑、
  顏色 ROI 政策、decision tuning、**校正目標**（`calibration` 的 target_luma
  與 tolerance）、偵測權重與 conf/iou/imgsz，以及上述的餘裕保留率
  （程式中的 `COLOR_IDENTITY_FIELDS`，有測試鎖住清單）。

  改動 `save_crops`、`model_version` 這類與顏色量測無關的鍵不會讓基準失效；
  改動校正目標、顏色門檻、ROI 或顏色模型內容則會失效並要求重建。

- **曝光、增益與光源亮度不屬於識別欄位**（`OBSERVED_CONDITION_FIELDS`）。
  這三個值是照度校正迴路從相機讀回來寫進設定檔的**結果**，不是人選的設定 ——
  迴路的目的正是調整它們來維持 `target_luma` 不變，所以每次校正都會落在不同數字。

  把它們納入識別的後果是：基準每次校正後都失效，操作員只能重建，
  而重建恰恰是把當天的偏移吸收成新的正常 —— 也就停掉了唯一能抓出壞曝光的量測。
  保留基準的話，壞校正會顯示為「顏色偏移超限」，那是可以處理的結論。
  因此這三個值只記錄在基準與檢查結果中，並在結果標題以
  「參考，不列入判定：曝光 A → B」呈現，**不影響判定**。舊的寫法「相機條件已變動」
  接在 NG 標題後面讀起來像是原因 —— 2026-10-05 曝光 +7%，但照度迴路已把線身亮度
  維持在 ±3.5 L* 內，真正的原因是擺放。

- 基準檔會記錄當時納入識別的欄位與其值、以及當時的相機條件，
  可用來稽核「為什麼失效／為什麼沒失效」。
  外部硬體調整（未進入設定檔者）仍需人員管理。

## 儲存與驗證

檔案在站點 `color_preflight` 根目錄下的 `<product>/<area>/<model_type>/`：

- `golden-reference.json`：目前正常基準、建立者、樣品 ID、上限、餘裕保留率、
  納入識別的設定欄位、當時的相機條件、建立時實測的最大波動與來源量測。
- `reference-*.json`：工程更換前封存的基準。
- `check-*.json`：完成的每日 OK／NG 量測、參考日期、上限、各格數值、對位偏移與分數、
  量測版本（`schema`）與來源快照，可供趨勢分析；建立新基準時也會重讀它們的影像來提議上限。

日常檢查不更新正常基準。寫檔採 temporary file + fsync + atomic replace；影像讀取與
判定由背景 QThread 完成，GUI 透過 Signals/Slots 更新。同一主視窗只開一個檢查視窗。

測試涵蓋重放樣品不判偏色、對位後仍抓得到亮度漂移、畫面改變時對位失敗、
只量穩定像素、以新基準重算過往取樣提議上限、偏移但辨識分數不變、單張／單格異常、
波動、位置匹配、過期影像、參考失效、
快照不完整、建立／更換基準、日常檢查、背景取消與 GUI 顯示，以及就緒檢查與實際
攔截共用同一組規則、單張失敗後保留已收集證據、識別欄位清單、餘裕保留率來源、
PIN 授權不外洩工程權限。現場仍需用正常／偏移實拍樣本驗證所選上限與誤報率。

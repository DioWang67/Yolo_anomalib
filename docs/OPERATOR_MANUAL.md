# AI 檢測系統操作手冊

文件對象：產線操作者、班組長、資料複核人員
適用程式：`yolo11_inference` 圖形介面
文件擁有者：製程／設備工程
最後核對：2026-07-29

本手冊只說明日常操作與異常回報。模型設定、相機校正、補訓參數、
資料庫還原及版本回滾由工程人員依
[工程維運手冊](ENGINEERING_MANUAL.md)執行。

## 1. 權限與責任

| 角色 | 可以執行 | 不應執行 |
| --- | --- | --- |
| 操作者 | 選擇產品／工位／模型、單次或自動檢測、查看紀錄、匯出報表、回報異常 | 修改模型設定、刪除證據、切換模型版本 |
| 班組長／複核人員 | 複核結果、排除不適合送訓的圖片、完成 LabelImg 標註、查看補訓進度 | 未經工程確認啟用位置檢測、放寬品質門檻 |
| 工程人員 | 工程設定、校正、補訓決策、版本切換、部署、備份、同步與回滾 | 以人工修改方式繞過品質 Gate |

「工程設定 PIN」用來防止誤觸，不等同 Windows 帳號或公司資訊安全權限。
PIN 不應張貼在機台或與一般操作者共用。

## 2. 開機與班前檢查

1. 確認相機、鏡頭、治具與光源沒有移位、鬆動或髒污。
2. 確認產品已清空，治具內沒有前一件工件。
3. 開啟整個部署資料夾內的 `yolo11_inference.exe`。不可只複製 EXE
   到其他位置執行。
4. 查看視窗底部的相機狀態；使用相機時，至少應顯示`相機已連線`，
   開始收到有效畫面後會變成綠色`相機就緒`。
5. 確認右下或畫面上的模型版本符合當班生產通知。
6. 先用一件已知正常品做首件確認。
7. 若首件結果、畫面亮度或框位與標準不同，停止投料並通知工程人員。

禁止用旋轉相機、移動治具或臨時調整燈光的方式讓異常品通過。

## 3. 主畫面

### 3.1 操作者區

- `預設`：一次切換產品、區域與模型。
- `產品`：目前檢測的機種。
- `區域`：同一產品的工位或拍攝區域。
- `模型`：通常選 `yolo`；只有工程文件明確要求時才使用其他模型。
- `自動模式`：產品到位並穩定後自動檢測。
- `開始檢測`：執行單次檢測，或啟動已勾選的自動模式。
- `檢測紀錄 >`：查看已保存紀錄、良率、異常與證據影像。
- `工程設定 >`：需要 PIN；一般操作者不需進入。

產品、區域或模型任一項未選好時，`開始檢測`不會啟用。

### 3.2 相機狀態

相機狀態常駐在視窗底部，不需要查看終端機：

| 狀態 | 意義 | 操作者動作 |
| --- | --- | --- |
| 黃色`相機連線中／重新連線中` | SDK 正在初始化或重連 | 等待完成，不要重複點擊 |
| 藍色`相機已連線` | 裝置已連線，尚在等待第一張有效影像 | 可開始檢測；若長時間沒有畫面，依異常處理 |
| 綠色`相機就緒` | 已收到有效相機影像 | 可正常操作 |
| 紅色`相機未連線／連線中斷` | 無法使用相機 | 停止自動投料，檢查線材後按狀態旁的`重新連線` |
| 灰色`相機已中斷` | 使用者已手動中斷裝置 | 需要相機時按`重新連線` |
| 灰色`圖片模式` | 目前使用保存影像，不從相機取像 | 僅用於允許的單張檢測或工程測試 |

相機不可用時，`自動模式`會停用，避免誤啟動；這不代表保存影像的單張
檢測功能故障。重連按鈕在檢測執行期間會停用，必須先安全停止。

### 3.3 結果區

- `原始`：相機或檔案的原圖。
- `處理後`：模型實際使用的前處理影像。
- `結果`：框線、類別與檢測結果。
- 大型狀態：`PASS`、`FAIL/NG`、`ERROR`、`READY` 或自動模式階段。
- 詳細結果：缺件、多件、錯件、顏色、順序、位置與推論耗時。

若工程設定隱藏了原始或處理後分頁，不代表影像沒有保存。

## 4. 單次檢測

1. 選擇正確的產品、區域與模型。
2. 不要勾選`自動模式`。
3. 將工件正確放入治具。
4. 按`開始檢測`，或在按鈕可用時按 Space／Enter。
5. 等待結果完成；單次檢測結束後按鈕會再次啟用。
6. 依現場作業標準處理 PASS 或 NG。

不要在推論尚未完成時移動工件、切換產品或關閉程式。

## 5. 自動模式

1. 確認使用相機且相機已連線。
2. 選擇產品、區域與模型。
3. 勾選`自動模式`；此時只是待命，尚未開始循環。
4. 按`開始檢測`。
5. 依畫面階段操作：

| 畫面狀態 | 操作者動作 |
| --- | --- |
| 等待產品到位 | 放入一件工件 |
| 定位中／檢測中 | 不要碰觸工件、相機或治具 |
| PASS／NG | 依結果分流產品 |
| 請取出產品 | 完整取走工件，等待下一循環 |

要停止自動模式時，取消勾選`自動模式`並等待停止完成。不要直接拔除相機、
切斷電源或強制結束程式。

## 6. 結果判讀

| 顯示 | 意義 | 現場動作 |
| --- | --- | --- |
| PASS | 已啟用的檢查全部通過 | 依作業標準放行 |
| NG／FAIL | 至少一項品質規則失敗 | 隔離產品並查看原因 |
| ERROR | 推論、相機、模型或儲存發生錯誤 | 不可當成 PASS；停止並通報 |
| READY | 系統待命 | 可進行下一次操作 |

常見異常原因：

| 畫面文字 | 代碼 | 意義 |
| --- | --- | --- |
| 缺件 | `MISSING` | 預期元件沒有被偵測到 |
| 元件錯置 | `WRONG_COMPONENT` | 類別或料件不符合預期 |
| 位置偏移 | `POSITION_SHIFT` | 偵測框相對位置基準超出容差 |
| 板件定位異常 | `BOARD_ALIGNMENT` | 整體板件或治具定位不可靠 |
| 多餘元件 | `UNEXPECTED_COMPONENT` | 出現不在規格內的物件 |
| 信心度不足 | `LOW_CONFIDENCE` | 模型信心未達門檻 |
| 顏色不符 | `COLOR_MISMATCH` | 顏色規則未通過 |
| 順序不符 | `SEQUENCE_MISMATCH` | 元件排列順序不符 |
| 推論錯誤 | `INFERENCE_ERROR` | 本次檢測沒有形成有效判定 |

一張圖可能同時有多個原因。`ERROR`與`NG`都不可自行改判為 PASS。

### 6.1 紫色 `DUP` 重複框

若標註圖出現紫色虛線與`DUP #來源 → #保留`，代表系統找到兩個幾乎完全
重疊、YOLO 原類別不同，但顏色複核相同的框：

- 正常實線框是後續數量與排列判定使用的有效框；
- 紫色虛線是已排除的模型重複候選，不代表實物真的多一件；
- 原始框、IoU 與排除理由仍保存在檢測紀錄；
- 若排除後仍為 NG，依畫面顯示的缺件、顏色、位置或順序原因處理；
- 同一正常品持續出現 DUP，或懷疑兩個實物被合併時，停止自行重測並通知工程。

## 7. 檢測紀錄

在主畫面按`檢測紀錄 >`。進入紀錄頁後可使用：

- 產品、工位、狀態篩選；
- 今日、近 7 日、全部時間或自訂日期；
- 每頁最近 100、250 或 500 筆；
- 上一頁／下一頁；
- PASS、NG、錯誤、良率摘要；
- 點選單筆後查看影像、模型、機台、工單、相機、複核結果與原因；
- 單擊右側「結果證據」預覽，可開啟較大的唯讀圖片視窗。

良率公式為：

```text
PASS / (PASS + NG)
```

推論錯誤不列入良率分母，但必須另行處理。

### 7.1 伺服器同步標籤

| 標籤 | 意義 |
| --- | --- |
| 伺服器同步未啟用 | 本機仍正常保存，尚未設定公司端上傳 |
| 待同步 | 已在本機保存，等待網路或背景同步 |
| 已同步 | 已取得公司 API 成功回應 |
| 同步異常 | 超過重試上限，需由工程／IT 處理 |

同步狀態不影響本機檢測判定；不得因「待同步」重做或刪除檢測。

## 8. 匯出 Excel 報表

1. 在檢測紀錄頁先設定產品、工位、狀態與時間範圍。
2. 確認上方統計範圍正確。
3. 按`匯出 Excel`並選擇檔名。
4. 匯出期間按鈕會顯示進度；需要停止時按`取消匯出`。
5. 完成後可選擇開啟所在資料夾。

報表包含：

- `報表摘要`：範圍、PASS、NG、錯誤與良率；
- `檢測明細`：檢測編號、產品、工位、模型、異常、複核與證據路徑；
- `異常統計`：各原因次數及占全部檢測的比例。

注意：

- 報表是匯出當下的唯讀快照，不會修改資料庫。
- 報表依畫面篩選條件輸出，不受表格目前只顯示哪一頁限制。
- 上限為 250,000 筆；超過時請縮小日期或產品範圍。
- 不要在匯出完成前開啟暫存檔或拔除儲存裝置。

## 9. 異常複核與資料回收

補訓入口位於 PIN 保護的工程設定頁，應由班組長或授權複核人員操作。
開始前必須停止檢測。

### 9.1 複核原則

先判斷實物真值，再看 AI 框，不可直接把 AI 預測當成標註答案。

| 現場真值 | 選擇 |
| --- | --- |
| AI 判 NG，實物確實 NG，框也正確 | 確認 NG（AI 判定正確） |
| AI 判 NG，但實物正常 | 實際 OK（AI 過殺） |
| 實物 NG，但框位置、數量或類別錯誤 | 確認 NG，但標註需修正 |
| AI 判 PASS，但實物 NG | 實際 NG（AI 漏檢） |
| 圖中確實沒有目標 | 實際無目標（負樣本） |
| 過曝、模糊、遮擋或無法判定 | 圖片無法判定（不採用） |

顏色問題使用畫面提供的顏色專用選項。顏色單一路由只進顏色校正資料，
不會啟動 YOLO 補訓。

現場發現未出現在候選清單中的漏檢時，使用`從已保存結果回報漏檢`。
外部圖片必須先用目前產線模型檢測並保存，不能直接送入補訓。

### 9.2 補訓清單

1. 完成選定範圍的逐張複核。
2. 開啟補訓清單。
3. 依`直接訓練`、`需要補標`、`顏色校正`篩選。
4. 雙擊縮圖放大確認。
5. 取消勾選誤入資料；取消只移除待送狀態，不刪除原始證據。
6. 確認後建立訓練資料。

### 9.3 LabelImg 標註

需要補框時系統會開啟 LabelImg：

1. 拖曳正確框。
2. 選擇正確類別。
3. 按 `Ctrl+S`。
4. 關閉 LabelImg，讓系統驗證並處理下一張。

漏檢案件至少要有一個有效框。空白 label、錯誤類別或越界框都不會送訓。
誤檢／錯類案件即使已有草稿框，也必須實際確認、修正並儲存。

## 10. 送出補訓與位置檢測

送出前會顯示本次的 Epochs、增強數、Batch、圖片尺寸，以及兩個位置選項。
一般情況使用工程核准的建議值。

### 10.1 `啟用位置檢測補訓`

- 未勾選：本次只補訓 YOLO，不建立或驗證新的位置基準。
- 勾選：執行位置校正、位置 Golden Set 驗證與 Position Gate。
- 此選擇只套用本次工作，不會記住到下一次，避免誤用。
- 至少需要 10 張合格的位置正常 OK 黃金樣本。
- 若現場位置檢測目前已啟用，系統會阻擋只補 YOLO 的工作，避免新模型與
  舊位置基準不相容。

### 10.2 `位置驗證通過後啟用現場位置檢測`

只有第一個選項已勾選時才可選：

- 不勾選：位置 Gate 通過後仍保留現場原本的啟用／停用狀態。
- 勾選：所有位置 Gate 通過後才啟用現場位置檢測。
- 任一 Gate 失敗都不會變更現場啟用狀態。

首次啟用或治具、相機、鏡頭改動後，必須由工程人員驗收 Golden Set，
不可只因訓練完成就直接勾選啟用。

### 10.3 可用的位置 Golden Set

位置驗證只接受：

1. AI 因`POSITION_SHIFT`判 NG，但人工確認實物位置正常的
   `位置檢測誤判，實物位置正常`案例；
2. 只有`POSITION_SHIFT`、且人工確認確實 NG 的案例。

缺件、錯件、顏色異常，或同時含多種失敗原因的圖片不會冒充位置樣本。

若顯示：

```text
Position golden manifest has no eligible samples...
```

表示 holdout 中沒有合格的位置專用證據。不要反覆重試；先收集並複核上述
兩類案例。若正常位置樣本不足 10 張，本次不要啟用位置補訓。

## 11. 補訓進度、續訓與停止

在`工程設定 > 模型補訓 > 補訓進度`查看：

- 等待處理；
- 累積改善案例；
- 等待補標；
- 準備資料；
- 模型訓練；
- 品質驗證；
- 部署模型；
- 部署完成；
- 失敗、已停止或心跳中斷。

`繼續這筆補訓`只會在可安全繼續且沒有既有程序占用時啟用。若按鈕為灰色，
先看目前說明；不要開第二個訓練視窗。

需要中止時使用`安全停止補訓`。安全停止可能等待目前 Epoch 或寫檔階段完成。
不要從工作管理員強制終止，否則狀態可能停在心跳中斷。

以下結果都不代表產線模型遭破壞：

- `累積改善案例`：資料已保存，但數量不足；
- `品質驗證失敗`：新模型未部署，現場仍使用原模型；
- `已停止`：可稍後選擇同一工作續訓；
- `部署完成`：新版本已發布，下一次推論會安全載入。

## 12. 班末作業

1. 等待目前檢測與儲存完成。
2. 停止自動模式。
3. 確認沒有未處理的 `ERROR` 或連續 NG 警示。
4. 需要交班時記錄產品、工位、模型版本、異常件數與待處理事項。
5. 正常關閉程式，讓資料庫、影像與背景同步安全結束。
6. 不要人工搬移、改名或刪除 `Result` 中的檔案。

## 13. 異常處置

| 現象 | 先做 | 何時通報 |
| --- | --- | --- |
| 相機無畫面／連線失敗 | 停止投料，確認線材與是否被其他程式占用 | 重連仍失敗，通知設備工程 |
| 畫面過亮、過暗或模糊 | 清潔鏡頭與治具，對照標準畫面 | 不可自行改曝光；通知工程 |
| 模型或設定不存在 | 核對產品、區域、模型選擇 | 選項正確仍失敗，通知工程 |
| `ERROR` | 隔離本次產品並記錄時間 | 立即通知工程，不可放行 |
| 連續 NG | 停線核對實物、治具與畫面 | 排除實物問題後仍持續發生 |
| 報表匯出失敗 | 縮小範圍、確認目的資料夾可寫 | 重試仍失敗或資料庫無法載入 |
| 同步異常 | 本機繼續檢測，不刪除紀錄 | 通知 IT／工程處理 API 或網路 |
| 補訓心跳中斷 | 不啟動第二筆相同產品工作 | 通知工程判定續訓或安全停止 |
| 位置 Golden Set 不足 | 取消位置補訓並收集合格案例 | 由工程確認樣本與啟用時機 |

## 14. 操作者禁止事項

- 不得把 `ERROR` 當成 PASS。
- 不得直接修改 `config.yaml`、模型權重或位置設定。
- 不得只複製、覆蓋或重新命名 `best.pt`／`best.onnx`。
- 不得刪除 `Result`、資料庫、備份或補訓工作目錄。
- 不得將公司 API Token 寫在 YAML、Excel、截圖或交班紀錄。
- 不得使用未經目前模型檢測的外部圖片直接補訓。
- 不得為了通過測試而移動相機、治具或放寬門檻。
